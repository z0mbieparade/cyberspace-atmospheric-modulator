# Shared userscript code

Code for any Cyberspace userscript: storage, URL matching, menu commands, long-press, accessible dialogs and inputs, theme colors, the update check, and the site's Settings > Userscripts tab. Nothing here knows about a particular feature.

The files are plain scripts concatenated into the bundle's IIFE, in the order `userscript.config.js` lists them. They read globals the script declares first, in `src/script-config.js`:

```js
const LOG_PREFIX = '[MyScript]';
const STORAGE_PREFIX = 'myScript_';   // published in users' localStorage: never change it
const GM_STORAGE_KEYS = ['debugMode', 'config', 'dismissedUpdateVersion'];
const SCRIPT_NAME = 'My Script';      // shown in the update banner
```

The build declares `VERSION`, and `SCRIPT_URL` from the header's `downloadURL`. Styles: `@use 'ui';` in the script's SCSS loads `_ui.scss`. Every class and custom property is `atmo-` prefixed, and `createDialog` sets the `--atmo-*` theme colors each time a dialog opens.

## Decisions

- **Concatenation, not modules.** The scripts ship as one self-contained `.user.js` with no runtime dependencies. Shared runtime files are plain scripts in the bundle's scope, so they read the consumer's globals directly.
- **Built in, not `@require`d.** A `@require` URL would load remote code at runtime on every user's machine. These files are reviewed and built into the bundle instead.
- **A folder, for now.** This was its own repo while two scripts used it. With nick colors built into Cyberspace Atmospheric Modulator it lives here; it stays free of feature knowledge so it can move out again for other scripts.
- **One `atmo-` prefix for all shared UI.** `UI_PREFIX` (`ui-dialog.js`) and `$p` (`_ui.scss`) set it: every class, custom property, data attribute and sessionStorage key here starts with it. It is specific enough not to collide with the site's own names (the site uses `cs-`). **Trade-off:** another script built on these files shares the prefix, so if two on a page are built from different versions of `_ui.scss`, the one that loads last restyles both.
- **Every script checks for updates.** The shared UI is only consistent while the scripts on a page run the same shared version, so each prompts its user to stay current.
- **The Userscripts tab is a hash, not a route.** The site has one route per settings tab and no catch-all to use: `/settings/userscripts` would match its `/:username/:postId` page. So the tab is `/settings/<current tab>#<hash>`: `#userscripts` by default, `#atmomod` here. It hides that tab's content while open, and a MutationObserver re-adds the tab after the site re-renders. **Warning:** a change to the site's settings markup can hide the tab. The menu commands still open the same settings.
- **Element ids carry a random per-script part.** Two scripts can have a dialog open at once, and each counts ids from 1.
- **Native controls under custom visuals.** Sliders and toggles are real `<input>` elements. They are visually hidden, and decorative elements are drawn over them. Keyboard, touch and assistive tech get native behavior while the look stays the same (WCAG 2.1 AA).
- **Exact dependency versions.** `sass` and `terser` are pinned exactly. Bumps go through the updates check, not a range.
